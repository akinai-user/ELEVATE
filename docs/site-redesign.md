# 情報設計の見直し

## 現状
- 静的HTML 19ページ。サービスTOPがDXのみ、人材は別URL配下で分断。
- TOPは抽象的なコピー、長いスクロール演出、NEWSが先。2事業・6サービスが読み取れない。
- 法人と求職者の導線が混在。人材のカテゴリ名が個別の「派遣」と混同。
- ITはSESとAIのみ。開発はSES本文に埋もれている。
- インタビューの本文はサンプル。実績としては使わない。
- LPと会社概要で資本金・従業員数が不一致。LPの会社概要を会社情報へのリンクに統合。

## 新構造と役割
- `/` 会社の2事業を理解し、目的別入口へ進む。
- `/service/` 2事業を横断して課題から選ぶ。
- `/service/hr/` 派遣・紹介・請負を比較する。
  - `staffing/` `recruitment/` `outsourcing/` 各サービスの支援内容・進め方・相談。
- `/service/it-dx/` 技術者支援・AI活用・開発を比較する。
  - `engineering/` `ai/` `development/` 各サービスの支援内容・進め方・相談。
- `/cases/` 既存本文にある開発支援例。顧客名・成果数値は創作しない。
- `/news/` 既存のお知らせ3件。
- `/company/` 企業情報・拠点。会社の考え方もここに集約。
- `/introduction/` 求職者の入口。派遣登録とフリーランス案件を分ける。
- `/introduction/staffing/` `/introduction/faq/` `/lp/` 既存の求職者向け情報を維持。
- `/registered/` 登録済みスタッフ向け。各申請フォームを維持。
- `/contact/` 法人相談（人材・IT/DX・その他の選択）。
- `/web-registered/` `/advance-payment/` `/transportation-expenses/` `/privacy/` 維持。

会社説明だけの薄いAboutページ、未確認の採用募集・代表メッセージは追加しない。
自社開発プロダクトは確認できないため創作しない。AI-LINKはAI導入支援サービスとして掲載。

## 共通UI
PC: サービス（2事業・6サービスの開閉メニュー）/ 支援事例 / 会社情報 / お知らせ。
求職者・登録スタッフのリンクは別のユーティリティ領域。法人相談を主CTAとする。
SP: 開閉ボタン、Escape、フォーカス管理、背景操作の抑止。サービス階層はアコーディオン。
白 + #4A0097。人・技術・空の写真を併用。本文への到達を遅らせるローディングは廃止。
旧サービスURLは新URLへの転送ページとして残し、リンクを失効させない。

## 実装
既存の静的配信を維持。Python標準ライブラリによる生成で共通テンプレートとコンテンツを分離。
実行時フレームワーク追加なし。フォームの既存action/送信項目を維持。

## 変更結果
- 新規URL：`/service/hr/` と配下3サービス、`/service/it-dx/` と配下3サービス、`/cases/`、`/news/`。
- 新規の情報ページ：IT・DXの比較ページ、システム開発、支援事例、お知らせ。
- 人材カテゴリと4つの既存個別サービス（人材3・SES）、AIは階層変更・移転。
- URL削除：なし。旧サービス6URLは転送ページに置き換え。
- 統合：SES内の開発支援例→支援事例、LP内の会社概要→会社情報。
- 削除したコンテンツ：仮の社員インタビュー、LP内の繰り返しキャンペーン、会社概要の重複。
- 削除したコード：Swiper依存、旧TOP・ヘッダー・フッター用CSS/JS、canvasローディング、旧HTMLテンプレート、旧本文全文一致テスト。
- TOP：具体的なファーストビュー → 2事業の入口 → ELEVATEについて → 課題別6サービス → 強み → 開発支援例 → 求職者向け入口 → NEWS → COMPANY → 法人相談。
- 新ナビ：サービス（2事業・6サービス）、支援事例、会社情報、お知らせ、法人のご相談。別枠でお仕事をお探しの方・登録スタッフの方。
- ブランド：白ベース・#4A0097、人物＋テクノロジー＋添付の青空写真。情報へのアクセスを妨げない軽いホバーのみ。

## 検証の限界
Chromeの操作が自動承認で許可されず、実ブラウザのスクリーンショット・視覚的なレスポンシブ検証は実施できませんでした。HTML／内部リンク／フォーム契約／JSモックの検証を実施。外部フォームへの実送信は行っていません。
